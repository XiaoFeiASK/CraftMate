# ADR-0002：执行内核用 TypeScript，不用 Go

- 状态：已采纳
- 日期：2026-11-02

## 背景

候选语言是 Node/TypeScript 与 Go。需要判断哪个更适合「大量 I/O 等待 + 少量状态变更」的编排系统。

## 决策

执行内核、接入端、语音、管理端全部用 TypeScript。

## 理由

- 四端共享一套类型与 zod schema，改字段不需要跨语言 codegen。
- 模型生态最成熟：流式、function calling、结构化输出、多 Provider。
- 单线程事件循环让仲裁器无锁，快速迭代期价值高。
- 真正的 CPU 热点（寻路、区块解析）在 Mod 里，不在内核。

## 后果

- 取消是协作式的，必须规范所有异步入口传 signal，否则会悬挂。
- 未捕获异常可能带走整个进程，需要守护进程和 `unhandledRejection` 处理。
- 内存和打包体积高于 Go。

## 重新评估条件

满足任一条件再讨论改 Go：

- 同时托管 3 台以上游戏实例。
- 评论吞吐持续超过 1000 条/秒。
- 内核 p99 调度延迟超过 200ms，且 profiling 证明瓶颈在运行时。
- 需要对外提供 SDK，要求单二进制分发。
