# 功能更新计划

> 目标：把当前骨架演进到「可连续直播一小时」，一个里程碑一个出口，不一次性实现最后形态。
> 「现在能跑什么」见 [实现状态](status.md)；架构约束见 [架构纵览](architecture.md)；
> 外部组件为什么这么选见 [外部接入](integration.md)。
>
> 本文只写**做什么、做到什么算完**。不排日期，里程碑按依赖顺序推进。

## 1. 基线

**已具备**

- 管理端：启动器式窗口、实时决策流、操作员四类指令、接入健康指示灯。
- 控制面：`/control`、`/health`、`/ingress`，zod 校验，`hello` 握手。
- 接入端：dyhub 订阅、事件归一化、去重限流背压、重连与健康上报。
- 内核：Stage A/B 仲裁、人格权重、承诺状态机、优先级产出。
- 存储：SQLite 建库与迁移、证据与决策落库、重启恢复、事件去重、动作幂等。
- 契约：观众事件、决策（含 `priority` / `skill`）、控制面、Bridge 半套。

**尚缺**

- 承诺状态没有落库，重启即丢。
- `/ingress` 只发送 token，服务端不校验。
- 没有模型 Provider、没有 TTS、没有 `/bridge` 服务、没有 Fabric Mod。
- 记忆、回放页面都没有；人格可编辑，但还没有试听与版本对比。

一句话：**「评论 → 决策 → 落库 → 重建」已经闭环；「决策 → 说话 → 动作」还没接上。**

## 2. 交付原则

1. **纵向切片优先**：每个 PR 必须有一条从输入到可观察结果的最小链路，不横切「先写完所有仓储」。
2. **契约先行**：跨进程或跨层的数据先进入 `packages/contracts`，再写实现。
3. **失败路径同批交付**：超时、非法输入、断线、重试至少有一条自动化测试。
4. **先落库再出声**：承诺、动作、语音的状态变更必须能从数据库解释。
5. **一次只动一个可回滚理由**：一个 PR 应该能用一句话说明「为什么需要整体回滚」。
6. **不预埋空包**：目标目录可以写进文档，但不创建没有引用、没有测试的空模块。

| 2.2 | ingress 端到端测试：连接、断线重连、房间关闭、洪峰 | 目前只有手工联调 |

## 14. PR 与完成定义

### 14.1 什么时候创建 PR

可以直接创建：

- 一个可观察行为端到端成立，测试覆盖主路径和至少一个失败路径。
- 一个契约变更已同时更新生产代码、消费方和契约测试。
- 一个迁移可执行、可回滚（前向修复或恢复备份），并有校验。
- 纯设计变更已能让另一位工程师据此实现，且没有未决的阻塞问题。

应该先开 Draft：

- 跨两个以上包的接口需要早期评审，但实现尚未完成。
- 迁移会改变已有数据，需要先确认回填和保留策略。
- 需要产品拍板（例如抖音接入方式），但代码骨架可以先评审。

Draft PR 只能用于「接口和边界已稳定」，不能代替设计文档。

不应该创建：

- 只有目录、空文件或 TODO，没有行为、测试或可评审设计。
- 主路径跑不通，靠注释说明「后续补」。
- 把多个互不相关的重构塞进同一个 PR。
- 迁移没有在空库和已有数据副本上验证。

### 14.2 大小与完成定义

- 业务代码变更小于 400 行（不含移动、锁文件、生成物、文档）。
- 最多触及 2 个运行时包；超过时先拆契约 PR 和实现 PR。
- 一个 PR 只解决一个主要问题；文件移动可以单独成 PR。

每个 PR 必须满足：

- `npm run typecheck`、`npm test`、`npm run build` 通过。
- 涉及 DDL 时，`npm run db:check` 通过；涉及连接或迁移时额外跑 `db:check:file`。
- 新增错误路径有测试或可复现步骤。
- 公开契约变化已同步 `packages/contracts` 和文档。
- 没有静默空操作；未实现的能力明确禁用或返回错误。

PR 描述模板：

```text
行为：用户能观察到什么
边界：本 PR 不做什么
数据：是否有迁移，如何验证
失败：超时、非法输入、断线时发生什么
回滚：如何撤回
```

### 14.3 分支与提交

- 分支：`feat/<slice-name>` 或 `fix/<slice-name>`。
- 提交按「契约 / 实现 / 文档」可分开，但一个 PR 内保持同一目标。
- 不提交生成物、`dist/`、本地数据库或日志。
- 推送前确认 `origin` 指向 `XiaoFeiASK/CraftMate`；未经确认不推送。

## 15. 风险与停止条件

出现以下情况时暂停扩展功能，先修基础：

- 迁移无法在已有数据上重复验证。
- 重启后决策、承诺或模式不一致。
- 同一事件被重复执行。
- 承诺先出声后落库。
- 观众文本进入系统提示。
- tick 线程出现阻塞 I/O。

这些是架构不变量，不是「稳定性阶段的优化项」。

### 时间盒

不排日程，但单个 PR 有时间盒：设计类 2 天内必须能评审，实现类 5 个工作日内必须能评审。
超时不是延期理由，是拆分信号。
