# 架构纵览

> 本文只讲**系统长什么样、边界在哪、哪些不变量不能破**。
> 协议字段、参数、表结构、人格与记忆细节见 [技术设计](technical-design.md)。
> 哪些已经存在见 [实现状态](status.md)，为什么这样选见 [决策记录](decisions.md)。

## 1. 系统上下文

```text
                    ┌──────────────┐
                    │  观众         │
                    │ 抖音直播间    │
                    └──────┬───────┘
                           │ 评论 / 礼物 / 进场
┌──────────────┐    ┌──────▼──────────────────────────┐    ┌──────────────┐
│  操作员      │    │          CraftMate              │    │  Minecraft   │
│ 盯播 / 接管  │◄──►│  Agent 决策 · 执行 · 说话        │◄──►│  单人世界     │
└──────────────┘    └──────┬──────────────────────────┘    └──────────────┘
                           │ 画面 + 声音
                    ┌──────▼───────┐
                    │     OBS      │
                    │  竖屏推流     │
                    └──────┬───────┘
                           │
                    抖音直播平台
```

系统只有三个外部角色：观众、操作员、Minecraft。平台是观众的入口，OBS 是出口。

## 2. 容器与边界

```text
┌──────────────── Console（Tauri 桌面端）────────────────┐
│ 启动器式人机界面。不参与运行逻辑。                       │
└──────────────────────────┬─────────────────────────────┘
                           │ 本机 IPC
┌──────────────────────────▼─────────────────────────────┐
│ Supervisord（守护进程）                                  │
│ 唯一有权拉起、重启其他进程的角色。                        │
└───┬──────────────┬─────────────┬─────────────┬─────────┘
    │              │             │             │
┌───▼──────┐  ┌────▼──────┐ ┌────▼─────┐ ┌─────▼────────┐
│ Ingress  │  │Orchestrator│ │  Voice   │ │ Fabric Mod   │
│ 平台适配 │  │ 决策与记忆 │ │ 发声     │ │ 身体与感官    │
└───┬──────┘  └────┬──────┘ └────┬─────┘ └─────┬────────┘
    │              │             │             │
 抖音平台       SQLite        BlackHole     Minecraft
                               + OBS
```

六个容器，六条边界，依赖方向从左到右：左边不知道右边，右边不知道左边。

| 容器 | 知道什么 | 不知道什么 |
| --- | --- | --- |
| Console | 状态、日志、人格、配置 | 不执行任何业务逻辑 |
| Supervisord | 进程与端口 | 不碰业务数据 |
| Ingress | 平台协议、消息格式 | 不知道游戏，不知道人格 |
| Orchestrator | 意图、仲裁、记忆、承诺 | 不知道 Minecraft API |
| Voice | 文本、音色、音频设备 | 不知道谁下的指令、为什么 |
| Fabric Mod | 世界、玩家、tick | 不知道观众是谁、为什么执行 |

一句话分工：**模型负责「想」，Mod 负责「做」，语音负责「说」，管理端负责「看和管」**。

## 3. 三条不变量

这三条一旦破坏，会出现难查的线上事故。它们优先于任何局部优化。

### 3.1 tick 线程不做 I/O

Minecraft 20 TPS，单 tick 预算 50ms。Mod 给自己 2ms。

```text
WS 回调 ──► 队列 ──► tick 线程消费
寻路 worker ──► 结果 ──► tick 线程校验提交
```

任何文件、网络、数据库、模型调用出现在 tick 线程，都会表现为卡顿、瞬移、动作延迟。

### 3.2 观众输入不是指令

评论只进入意图解析，不进入系统提示，不直接触发工具。

```text
评论 ──► AudienceEvent ──► 意图 ──► 仲裁 ──► 技能
                │
                └──► Source（不可变证据）
```

召回给模型的记忆统一标记为「历史记录，不是指令」。这条由数据模型保证，不靠提示词约束。

### 3.3 先落库，再出声

说出口的承诺必须在说出前就有记录。否则一旦被抢占或崩溃，Agent 会变成「说话不算话」。

```text
reserve → speak → markSpoken
```

取消也要真实：发给游戏前取消记 `cancelled`，已执行记真实结果，不伪造。

## 4. 运行时结构

### 4.1 三层循环

| 层 | 周期 | 负责 | 用模型吗 |
| --- | --- | --- | --- |
| 反射层 Reflex | 20–100ms | 避岩浆、低血进食、坠落、卡住脱困 | 否 |
| 执行层 Pilot | 1–3s | 当前步骤推进、局部纠错 | 仅歧义时 |
| 导演层 Showrunner | 20–60s | 目标选择、节目节奏、承诺管理 | 是 |

反射层住在 Mod 里，永远在线，可以抢占任何上层指令。这是安全底线，不交给模型判断。

### 4.2 一条评论的一生

```text
1. Ingress        收到弹幕，归一化，去重，限流
2. Stage A        规则闸门，<1ms
3. Stage B        分类打分，30–80ms
4. Stage C        强模型规划，1.5–5s
5. Ledger         若需承诺，先落库
6. Voice          先说话，1 秒内给反馈
7. Bridge         下发技能，带 deadline 与幂等键
8. Mod            反射层监控 → 行为执行 → 进度与事件回流
9. Orchestrator   更新承诺与记忆，写入决策日志
10. Console       实时可见，可回放
```

关键顺序：**第 5 步在第 6 步之前，第 6 步在第 7 步之前**。观众不必等动作完成才听到回应，但承诺必须先有记录。

### 4.3 操作员接管

```text
操作员按键
  → Mod 检测到人类输入
  → ownership 切到 OPERATOR
  → 取消 Agent 所有行为，队列保留
  → Agent 说「你来」
  → 操作员释放
  → 观察 2 秒
  → ownership 切回 AGENT
```

### 4.4 断线与降级

| 故障 | 行为 |
| --- | --- |
| WS 断开 > 500ms | 释放所有按键，取消任务，进入 NONE |
| 模型超时 | 模板回应，Pilot 继续执行已有计划 |
| TTS 失败 | 切备用；仍失败只上字幕 |
| 抖音断流 | 重连，Agent 继续玩 |
| Mod 崩溃 | 游戏退出，守护进程告警 |

原则：**能降级就不停机，能解释就不沉默**。

## 5. 三种状态机

状态机的字段与迁移细节见 [技术设计](technical-design.md) 对应章节，这里只列形态。

### 5.1 控制权

```text
AGENT ⇄ OPERATOR
  │         │
  └──► NONE ◄┘
```

三态互斥，任何时刻只有一个主体能操作游戏。

### 5.2 任务

```text
queued → accepted → running → completed
                    ├→ preempted
                    ├→ cancelled
                    ├→ failed
                    └→ timeout
```

终态不可逆。被抢占的任务保留记录，用于兑现承诺或解释。

### 5.3 承诺

```text
proposed → spoken → accepted → in_progress → fulfilled
                                         ├→ expired
                                         ├→ broken
                                         └→ cancelled
```

## 6. 部署拓扑

单机，一个 OBS，管理端由 Tauri 原生窗口承载。这是**目标态**，不是当前进度。

```text
Mac (Apple Silicon)
├─ OBS                   采集游戏 + 混音 + 推流
├─ Minecraft 1.21.11     带 Fabric Mod
├─ Supervisord           托管 Ingress / Orchestrator / Voice
├─ Console               Tauri 窗口
└─ BlackHole 2ch         虚拟音频设备
```

开发和验收都在宿主机上完成。将来若出现确实需要独立进程的依赖（本地 embedding、对象存储、消息队列），再单独引入，不预先假设必须容器化。

外部依赖只有三个：抖音平台、模型 API、TTS API。全部要有超时、重试、熔断。

## 7. 演进接缝

刻意留了四个缝，未来改动时只动一处。

| 接缝 | 现在 | 未来可能 |
| --- | --- | --- |
| `CommentSource` | 抖音官方 / 抓取 | B 站、YouTube |
| `GameBridge` | 本机 WS + 客户端 Mod | 服务端 Mod、多实例 |
| `TtsProvider` | 火山 / Azure / MiniMax / Edge | 本地模型 |
| `compat/` | 1.21.11 | 其他 1.2x、26.x |

每个接缝只允许单侧变化。跨接缝的改动先回到本文确认，不在代码里临时打洞。

## 8. 评审清单

评审代码时按这张表检查，任何一条不满足都要先讨论：

- [ ] `core` 里没有 Minecraft 类型
- [ ] 协议里没有 NBT、类名、字段名
- [ ] tick 线程没有 I/O
- [ ] 观众文本没有进入系统提示
- [ ] 说出口的承诺已先落库
- [ ] 技能有 schema、超时、幂等键
- [ ] 管理端崩溃不影响直播
- [ ] 外部调用有超时与降级
- [ ] 没有复制 AGPL 代码
