## D-01 游戏执行层用 Fabric Mod

Mineflayer 适合协议实验，但难以稳定操作真实登录账号、真实渲染、相机与本地客户端状
态。Fabric Mod 能接入权威客户端世界和输入路径。

**后果**：需要维护 Java、Mixin 和版本映射；tick 线程纪律成为硬约束。

**重新评估**：仅当目标改为离线机器人或可接受非真实账号时。

## D-02 内核用 TypeScript

管理端已用 React，模型流式生态成熟，跨进程契约可用同一份 zod 定义。Go 的取消和部署
优势不足以抵消三语言、多 codegen 的边界成本。

**后果**：必须用 `AbortController`、显式队列、有界内存和测试弥补单进程故障隔离不足。

**重新评估**：多实例、超过 1000 评论/秒、p99 调度延迟超过 200ms，或需要单二进制 SDK。

## D-03 客户端 Mod 驱动真实玩家

目标是一个账号、一个身体、真实第一人称画面。客户端 Mod 比操作系统级键鼠或服务端
NPC 更直接。

**后果**：人和 Agent 不能同时操作，必须实现三态控制权。

## D-04 本地单人世界

单机可控制地形、延迟、权限和存档；单人世界在客户端仍是集成服务器，能拿到权威状态。

**后果**：不做多玩家同步、反作弊和服务器运维；正式直播必须使用专用存档。

## D-05 Tauri 桌面管理端

管理端是本机操作台，不是云端后台。Tauri 复用 React 并避免 Electron 的整包运行时。

**后果**：桌面打包依赖 Rust；浏览器预览只是开发形态。

**重新评估**：需要远程多人运维、跨平台自动更新或服务端权限体系时。

## D-06 compat 层隔离版本

版本差异集中在 `compat`，`core` 不依赖 Minecraft 类型，协议只使用语义 ID。

**后果**：新版本要写适配层，不能假设全局通用。

## D-07 抖音接入双路径

保留官方开放能力和受控抓取两条可能路径，运行时只接入当前可验证的 dyhub sidecar。

**后果**：接口以内部 `AudienceEvent` 为准，不把平台字段泄漏进决策。

**重新评估**：官方 API 覆盖所需事件且可稳定申请后收敛。

## D-08 不复制 AGPL 代码

AstrBot 只参考公开文档和架构思想，不复制源码；本项目采用宽松双许可。

**后果**：借鉴要记录来源，实现独立编写。

## D-09 默认人格用大肥鱼

社区已有清晰人格和音色认知，便于首播辨识。

**后果**：使用时必须核查社区授权边界，不冒充官方角色。

## D-10 双许可

采用 MIT OR Apache-2.0，方便库复用并保留专利条款。

**后果**：引入依赖时检查兼容性。

## D-11 暂不做完整风险分级与回滚

首播以低风险动作和操作员急停为主，先交付可观察闭环；完整存档回滚延后。

**后果**：禁止危险技能进入白名单；世界破坏动作必须可人工验收。

## D-12 模型先用 DeepSeek

先用 OpenAI 兼容协议验证稳定性、成本和延迟，不绑定专有 Agent 框架。

**后果**：Provider 抽象必须保留；价格与预算按小时记账。

## D-13 音色参考社区授权

默认音色参考社区大肥鱼风格；是否复用具体音色取决于服务可用授权。

**后果**：不得宣称官方授权；配置必须可更换。

## D-14 首播单一主线

先完成一条主线，允许约 20% 被弹幕打断，避免多目标调度压垮执行层。

**后果**：镜头和复杂节目编排不是首播验收项。

## D-15 寻路自研

自研基于区块快照的寻路，便于取消、预算和协议集成；Baritone 只作对照。

**后果**：需要专门测试卡住、重试、目标失效和 worker 线程校验。

**重新评估**：出现成熟、许可证兼容且可精确取消的库。

## D-16 dyhub 作本机 sidecar

dyhub 提供本机事件流，避免云中转和网页动作混入数据层。

**后果**：平台字段在 Ingress 归一化；dyhub 自身故障必须降级为 source 状态。

## D-17 MCPFabric 只作候选适配

MCPFabric 的静态映射保留为候选，不因配置存在就宣布真实执行能力。

**后果**：真实身体以 `mods/craftmate-body` 和实测协议为准；候选映射未验证前不接入
运行时。
