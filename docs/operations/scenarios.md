# 场景回归

> 单元测试证明协议和纯函数正确；本清单证明“从观察到动作再到世界证据”的完整链路在真实
> 1.20.1 客户端的专用存档里成立。每个场景都要有 `changes` 或服务器侧方块查询作为证据，
> 不能把“动作已下发”“进度到了 100%”或 `unconfirmed` 当成完成。

## 运行顺序

```bash
npm run typecheck
npm test
npm run db:check
npm run check:bridge          # 真实客户端已连接
npm run check:control         # 规划 → Bridge → Mod 的完整链路
```

场景回归在专用存档 `craftmate-autonomy` 中手动或脚本执行。每个场景开始前记录身体位置、
背包、血量和世界时间；结束后用 `changes`、方块查询或背包差量断言结果。失败场景必须保留
当时的 `problem`、`remaining` 和 `attempts`，不要只截一张“看起来在动”的图。

## 矩阵

| # | 场景 | 前置 | 期望动作 | 世界证据 | 失败时应看到 |
| --- | --- | --- | --- | --- | --- |
| 1 | 空手开局 | 空背包、附近有树 | `chop_tree` → `craft` 木板/工作台 | 原木减少、木板增加、工作台方块出现 | 可见树但 `chop_tree` 返回 `E_WORLD_CHANGED` 或不可达 |
| 2 | 木镐链路 | 有原木、无工作台 | 合成木板 → 工作台 → 木棍 → 木镐 | 背包出现 `wooden_pickaxe`，工作台仍在 | 缺料时报告缺什么、缺几个，而不是反复重试 |
| 3 | 石具与矿道 | 有木镐、附近有石头 | `mine_block` / `descend` | 目标方块变空气，掉落物被拾取 | 服务端复原方块必须判失败 |
| 4 | 夜晚庇护 | 夜间、露天 | 放置方块围合或挖入山体 | 周围出现封闭方块，血量不再下降 | 找不到安全点时明确报告，不站着挨打 |
| 5 | 岩浆边 | 站在岩浆 2 格内 | 反射先退开，再规划离开 | 与岩浆距离增加，血量不继续下降 | 反射事件有 `lava`，但没有主动移动证据 |
| 6 | 苦力怕贴脸 | 4 格内生成苦力怕 | 反射后退/举盾，随后选择打或撤 | 存活且距离拉开 | 反射触发但下一轮仍回到原动作 |
| 7 | 高处坠落 | 从 >3 格落下 | 反射报告 `falling` | 落地后血量与位置一致 | 把普通跳跃误报成坠落 |
| 8 | 溺水 | 水下、氧气下降 | 反射报告 `drowning` 并上浮 | 氧气恢复、头部出水 | 只报告不上浮，或反复搜索出口 |
| 9 | 自动垫桥 | 5 格壕沟、有整方块 | `goto` 触发垫桥 | 对岸出现连续方块，身体到达对岸 | 没有垫脚料仍规划桥，或走到一半停住 |
| 10 | 楼梯脱困 | 1–2 格深坑 | 挖台阶或垫脚离开 | 身体 y 回到地面，路径不再 `NoPath` | 原地跳、反复重算同一条路 |
| 11 | 箱子存取 | 附近有箱子、背包有杂物 | `deposit` → 再取回 | 箱子与背包数量互补 | 窗口打开但物品未移动却报成功 |
| 12 | 熔炼铁器 | 有熔炉、粗铁、燃料 | `smelt` | 产物进背包，燃料减少 | 把“开始烧”当成“已产出” |
| 13 | 床与重生点 | 有床、夜间 | `sleep` | 时间推进到白天，重生点更新 | 白天/雷雨时直说白跑一趟 |
| 14 | 空场节拍 | 无评论 45 秒、身体在线 | 环境台词（不带技能） | `decision_log` 出现 `idle:*` 决策，语音有字幕 | 空场完全静默，或每 5 秒重复同一句 |
| 15 | 危险反应 | 触发 `reflex` | 主动短台词（不带技能） | `decision_log` 出现 `reflex:*`，冷却内不重复 | 只写 `world_event`，直播没有反应 |
| 16 | 分段续跑 | 长距离 `goto` / 大批量挖掘 | 到预算返回 `remaining` + `nextHint` | 下一轮从剩余进度继续，不重复副作用 | 超时后从头重做或永久失败 |

## 证据写法

每个场景的结果至少包含：

```text
场景：<编号 + 名称>
身体：<位置 / 血量 / 饥饿 / 手持>
决策：<decision id + skill + outcome.status>
证据：<changes 列表 / 方块查询 / 背包差量>
未确认：<unconfirmed 列表，没有就写“无”>
失败条件：<problem / remaining / attempts>
```
