```bash
npm run typecheck
npm test

git diff --check

cd mods/craftmate-body
./gradlew test build
```

2026-11-17 当前工作区（Node/TypeScript 部分已重跑，Java 身体未重跑）：

- `npm run typecheck`：通过；
- `npm test`：801 个测试、75 个 suite 全部通过；
- `npm run build`：Admin Console 生产构建通过；
- `git diff --check`：通过；
- `npm run db:check` / `db:check:file`：2026-11-16 本地通过迁移、约束、视图、FTS 和真实 WAL 文件库；
- `./gradlew test build`：2026-11-16 本地通过 245 个 JUnit 测试与 Fabric 1.20.1 构建；

本次文档更新未重跑数据库和 Java 身体检查；真实游戏链路的验收状态仍以下文证据为准。

CI 不覆盖真实直播间、供应商计费、音频硬件、Minecraft 图形进程或桌面安装包。

真实身体通道检查需要 Minecraft 已连接：

```bash
npm run check:bridge
```

该命令等待真实 `mine_block` 完成，并校验每个目标方块的位置证据。默认挖 1 个
`minecraft:stone`；可用 `CRAFTMATE_CHECK_BLOCK` 和 `CRAFTMATE_CHECK_COUNT`
覆盖，最多 64 个。

完整控制链路：

```bash
npm run check:control
CRAFTMATE_CHECK_COUNT=3 npm run check:control
```

脚本通过 `/control` 注入“只砍 1 根木头”，再核对 `decision_log` 与
`action_attempt` 中的真实方块 ID、坐标和终态。逐场景矩阵见
[场景回归](scenarios.md)。

## 2. 状态定义

| 状态 | 判定 |
| --- | --- |
| 已实现 | 仓库命令可复现，或已有本机真实环境证据 |
| 部分 | 主路径存在，但关键环境、终态或长时间行为未验收 |
| 未实现 | 没有运行时代码 |

协议测试、模拟身体或供应商返回成功都不能写成游戏结果成功。目标里程碑必须有
身体 `changes` 证据；`unconfirmed`、空结果或“动作看起来开始了”都不算完成。

## 4. 自主闭环

**已实现**

- `GoalTreePlanner` 决定阶段、里程碑和任务方向；`nextTaskForStage` 生成阶段内
  原子任务；模型不参与目标模式的逐步执行。
- 一次最多下发一个技能；终态后等待新观察再规划。
- 低血量、近身威胁、食物、可用镐和工作台是确定性前置，不能由观众提议或模型跳过。
- 完成必须带身体世界证据；空结果、`unconfirmed` 和旧快照不推进里程碑。
- 失败分类、路线黑名单、恢复路径、最长 6 秒退避和重新观察均有自动化覆盖。
- legacy 路径在铁套材料和工作台就绪时可编译 `run_plan`，连续完成熔炼和制作；
  契约和身体都强制 32 步/180 秒上限、禁止嵌套、目标族白名单和类型化 guard。
  矿族 guard 会等待最多 5 秒的有界观察，扫描完成仍不满足时返回明确原因，不把
  未扫完当作不存在。
- 合成/熔炼计划由知识图的 AND/OR 依赖编译，不再手写铁套顺序；多个目标的库存
  预留共享，买不起的装备直接跳过，缺少矿石/原木时不会凭空生成步骤。
- `GoalTreePlanner` 默认用目标树调度：阶段骨架完整、当前阶段懒展开，技能失败先
  重试一次再换任务，阶段阻塞后按前置条件切换，低血/工具失效走根下 interrupt。
- `goalProgress.taskTree` 返回完整节点、当前路径、状态、尝试次数、失败原因和
  interrupt 标记；控制台只读展示，不提供节点编辑或跳过。
- 旧 v1 树快照会被丢弃重建；旧会话目标标题恢复时按预设推断 `goalKind`
  （钻石标题→`diamond-set`，海崖小屋/自由生存→`dragon`），迁移结果重新持久化。
- `CRAFTMATE_GOAL_ENGINE=legacy` 可回退到 `MissionGoalPlanner`，此时任务树仍只是
  只读投影。知识图分支以 pending 子树挂在当前任务下，完成时用同一份证据整支标记成功。
- 连续挖掘在当前 `mine_block` / `chop_tree` 内完成“找目标→接近→破坏→拾取→重扫”，
  每个新目标重置接近重规划预算，只有达到 `count`、无目标、背包满或持续危险才返回。
- `goto` 使用可恢复 A* 搜索，在当前路线安全走完的同时分片预取下一段；`NavGoal`
  支持半径目标，木门/栅栏门/活板门可开启，梯子和藤蔓可通行。
- Body 每 tick 用 3ms 预算扫描半径 5 的已加载区块调色板，输出 `landmarks` 与 `scan`；
  要塞、下界要塞、末地传送门等已接入规划，并在会话结束时写入世界记忆。
- B：原版第三人称背面直接使用轨道视角，以 Agent 眼睛为球心、逐帧看向躯干；
  默认 8.5 格，滚轮在 2.5–20 格间缩放，左键拖拽和方向键调整角度。中心、
  角度和半径均带弹簧；身体转向不会自动拖动镜头。通过 `getMaxZoom` 绕过原版
  缩距，遮挡方块以 28% alpha 重绘而玩家本体不透明，并做 120ms 淡入淡出。
  第一人称和第三人称正面保持原版，鼠标按键 5 可随时切回第一人称；自动化覆盖
  轨道限位与弹簧收敛，真机操作手感待复测。
- A：铁矿族匹配覆盖 `iron_ore` / `deepslate_iron_ore`，矿脉状态走
  `NOT_OBSERVED → OBSERVED_NOT_PLANNED → CANDIDATE_READY`；只要有真实暴露面且
  在交互距离内，就允许开挖，不再要求眼睛射线完全无遮挡。连续掘进/下潜会在每个
  台阶前顺手挖掉可达的暴露矿石，铁优先于铜/煤。
- 背包容量只统计主背包和快捷栏，不把四件已穿戴护甲算成四个占用格；铁套齐全后
  不再误报“背包已满”。
- 镐子低于 12 次耐久时主动结束当前掘进段，先补镐或回地表；无镐且无木料时，
  若离矿道台阶太远则改用背包方块垫高脱困，不再反复重发必失败的 `goto`。
- 目标运行时恢复、观察间隔、死亡预占和策略熔断均有自动化覆盖。

**未验收**

- 从目标模式开启到击杀末影龙的全链路。
- 多次连续 `run_plan`、跨重启续跑和长时间站点复用。
- 真实存档中的区块扫描覆盖率、地标坐标误差和跨维度 `landmarks` 持久化。
- 连续挖掘多棵树/多组矿脉时的门、梯子、藤蔓和拾取重试。
- B 真机：多朝向、横移、贴墙、第一人称、操作员接管/释放的长时间切换。
- C 真机：从 `CraftMate-4h-2026-11-13w` 继续到钻石镐、钻石剑和钻石护甲全链路。
- 4 小时无人接管稳定性、感知 P95 和策略熔断现场表现。

## 6. 抖音与语音

**抖音已实现**：dyhub 订阅、归一化、10 分钟去重、512 有界队列、每秒上限、
指数退避、健康上报、Orchestrator 自动启停。

**自动化**：本地 dyhub stand-in 覆盖订阅、断线重连、房间关闭、坏输入和洪峰；
Ingress 上报 `received/forwarded/queued/dropped`、`dropReasons`、`reconnects`
和有界无文本 `recent` 事实。

**本机检查**：Web 预览在三档宽度无横向溢出；工作台不渲染耳语或弹幕原文；
房间切换后计数和去重窗口清零，重启后仍显示新房间。

**未验收**：真实抖音房间字段、评论延迟、洪峰和风控。

**语音已实现**：Seeduplex 实时 WebSocket、24kHz PCM、字幕、抢占和失败上报。

**未验收**：BlackHole/OBS 路由、实播音频延迟、设备切换和长会话。

## 7. 明确不存在

- `services/supervisord`。
- 自动配置的 BlackHole/OBS 集成。
- 抖音开放平台 SDK。
- embedding 或向量库。
- 自动沉淀长期记忆的技能。
- 桌面多平台打包、Fabric 集成测试或发布流水线。
- 从自由文本直接生成任意技能的目标规划器。

以上出现实现时，必须同步本清单和[架构总览](../reference/architecture.md)。
