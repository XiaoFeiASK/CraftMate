# 目标树调度

> 目标树是目标模式唯一的调度源，不是执行日志的二次投影。它只存在于 Agent
> 侧；Bridge 和身体仍只收到一个 `SkillCall`。

## 1. 为什么是一棵树

目标模式需要同时回答三个问题：

1. 现在处在长目标的哪个阶段、哪个里程碑？
2. 这一步具体执行什么技能，失败后换哪条任务？
3. 安全事件打断后，原来的进度还在不在？

线性脚本只能回答“下一步”，回答不了“为什么是这一步”和“打断后回到哪里”。
目标树把这些问题放在同一份持久化状态里，同时保持一个执行叶子：同一时刻最多
只有一个技能在途。

## 2. 六类节点

| 节点 | 作用 | 子节点 |
| --- | --- | --- |
| `goal` | 根节点，绑定 `goalKind` 和验收条件 | 所有阶段 + 最多一个安全中断 |
| `stage` | 生存链的大阶段，进入前检查前置阶段 | 里程碑 |
| `milestone` | 可验证的世界事实 | 任务 |
| `task` | 一次策略选择及其参数 | 技能 |
| `skill` | 真正下发给身体的 `SkillCall` | 无 |
| `interrupt` | 低血、工具失效等抢占 | 安全恢复任务 |

只有两种容器模式：

- `sequence`：按定义顺序推进；
- `selector`：选择第一个可执行分支，当前用于目标根。

不引入并行节点、装饰器节点或通用行为树编辑器。节点种类和模式是固定的，
新增行为应表现为新的任务/里程碑，而不是新的解释器语义。

## 3. 调度规则

1. 根节点一次性建立完整阶段骨架；阶段节点先全部存在，但只有当前阶段展开
   里程碑。
2. 当前阶段按定义顺序检查里程碑：世界事实已满足的直接标记 `succeeded`，
   证据回退的重新验证。
3. 第一个未完成里程碑展开任务；任务再展开一个技能叶子。
4. `GoalRuntime` 只接收规划器返回的一个 `nextTask`，不自行选分支。
5. 技能终态通过 `noteSettlement` 回写树：
   - `completed`：技能和父任务成功，等待下一次观察验证里程碑；
   - `failed`：同一技能先重试一次，第二次失败后父任务失败，里程碑尝试
     fallback；
   - `cancelled` / `preempted`：不计失败，节点复位，下一次重新求值。
6. 阶段可以在阶段边界切换，但不能跳过未完成的前置阶段。mission 提议的
   后置阶段若不满足入口条件，规划器回退到最早可执行阶段。
7. 同一策略最多创建两个任务节点；仍失败则阻塞该里程碑，避免无限重试。

阶段内任务由 `nextTaskForStage` 生成；mission 只提供阶段方向建议，不能直接创建
技能叶子。`run_plan` 仍可由 legacy 编译路径生成，默认树引擎当前逐个下发原子任务。

## 4. 安全中断

根节点下只有一个 `interrupt` 节点，触发器为：

- `danger`：生命值过低，或低血且近身有敌对实体；
- `tool-lost`：工具丢失，或已进入石具阶段却没有可用镐；
- `operator`：预留给操作员接管；当前实现用运行时暂停游标表达，不伪造技能。

进入中断时，当前阶段游标写入 `pausedCursorId`，技能节点复位；恢复后重新读取
世界事实，不把打断计入策略失败。中断节点被阻塞时，规划器返回明确原因，而不是
继续下发普通任务。

## 5. 目标类型

| `goalKind` | 终点 |
| --- | --- |
| `dragon` | 身体报告 `dragonDefeated` |
| `diamond-set` | 钻石镐、剑、头盔、胸甲、护腿、靴子六件齐全 |

旧会话里的标题会按预设或关键字推断目标类型：“海崖小屋 / 自由生存”迁移到
`dragon`，“钻石装备”标题迁移到 `diamond-set`，不会凭空产生新的目标类型。

## 6. 持久化与回退

- `TaskTreeSnapshot` 当前为 `schemaVersion: 2`；v1 快照会被拒绝并由规划器重建。
- `GoalRuntime` 保存树的完整快照和当前节点，重启后先恢复，再等待新观察；
  不会重放旧技能。
- 默认使用树引擎。设置 `CRAFTMATE_GOAL_ENGINE=legacy` 可回退到
  `MissionGoalPlanner`；回退路径仍把任务树当作只读投影。
- 控制台展示完整树、当前路径、状态、尝试次数和失败原因，但不提供节点编辑、
  跳过或重试按钮。操作员只能换目标、暂停/继续。

## 7. 边界

树负责“现在做什么、为什么、失败后换什么”，不负责：

- Minecraft 坐标、寻路、瞄准或 tick 内反射；
- 在身体内逐步重规划；
- 并行执行多个技能；
- 生成新的 `GameActions` 技能；`run_plan` 仍是身体能力，默认树引擎按原子任务
  展开，legacy `MissionGoalPlanner` 路径可按需编译。

这些仍由 Bridge 和 Fabric 身体负责。
