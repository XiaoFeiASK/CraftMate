# Minecraft 生存玩法调研与 Agent Playbook 方案

> 调研日期：2026-11-11  
> 适用版本：Minecraft Java Edition 1.20.1  
> 目的：把网上攻略转成 Agent 可以执行、验证和恢复的结构化玩法知识，而不是把整本 Wiki 塞进模型上下文。

## 1. 结论先行

当前 Agent 的主要问题不是“不知道合成表”，而是缺少一层真正的玩法策略：

- 知道“缺木镐”，但不知道“现在应该先回家、先做床，还是继续挖”。
- 知道“附近没有铁矿”，但不知道“应该换区域、下矿、回家，还是先补火把和食物”。
- 任务失败后只区分“重试 / 换候选”，没有“诊断失败原因 → 选择恢复策略”。
- 模型只在候选之间排序，但候选本身由固定阶段顺序生成，知识错了，模型再聪明也只能选错。

适合的输出不是一篇更长的攻略，而是一套 **Playbook Cards（玩法卡）**：

```text
当前世界事实
  -> 选择 1 张当前适用的玩法卡 + 1~2 张备选卡
  -> 生成少量合法任务候选
  -> 模型只负责选择、解释和决定是否换卡
  -> 执行结果和失败类型回到玩法卡
  -> 下一次选择恢复卡或下一张推进卡
```

一句话：**知识应该进入确定性规划器，模型只拿当前处境的少量卡片做选择。**

## 2. 真人玩家的实际生存主线

Wiki 的教程按“时间”讲，但真人玩的时候实际是在维护一个优先级队列：

```text
立即保命
  > 今晚有安全屋/床/光
  > 当前工具和食物够不够完成下一件事
  > 长期目标需要的关键资源
  > 探索和建设
```

### 2.1 第一天

早期攻略的共同顺序是：

1. 找树，徒手拿原木。
2. 原木 → 木板 → 工作台。
3. 木板 + 木棍 → 木镐。
4. 找石头，至少拿到 3~19 块圆石，升级石镐、石剑/石斧。
5. 找食物，优先击杀羊、牛、猪、鸡；羊还提供床需要的羊毛。
6. 天黑前建立安全屋，放火把，尽量做床。
7. 有床就睡觉；没有床就待在封闭安全屋里，做合成、熔炼、整理物品，不要继续远距离砍树或探索。

关键不是“食物必须在铁器之前完成”，而是：

- 白天优先解决工具、庇护所和照明。
- 饥饿低于安全线时才把食物提升为最高优先级。
- 夜里没有床时，最危险的行为是站在室外做长时间砍树/挖矿。

### 2.2 第二天和第三天

玩家的重点从“活过今晚”转成“建立可持续的补给和下矿能力”：

- 食物：熟肉、面包、农田、动物养殖；食物是回血和冲刺的资源。
- 矿物：煤、铁是早期核心；挖矿要带火把、方块、食物和备用工具。
- 装备：铁剑、铁镐、盾牌、至少部分铁甲；有弓和箭更安全。
- 探索包：床、方块、火把、食物、水桶、备用工具、返回标记。
- 家园：箱子、床、工作台、熔炉、照明；下矿前把不必要物品存回家。

Wiki 的第二/第三天教程还强调：

- 下矿要预留返回路径，不能只会“往下挖”。
- 洞穴比盲挖更高效，但需要武器、食物、方块和照明。
- 发现岩浆、深洞或怪物时，先封路/撤退，不要用低级工具硬闯。
- 探索前把重生点、床和补给放在安全位置。

### 2.3 进入下界

下界不是“有铁镐就进去”的阶段，至少需要：

- 铁剑或更好的近战武器。
- 弓和箭，或足够的远程手段。
- 铁甲，最好有一件金甲避免猪灵主动攻击。
- 食物、方块、火把、打火石。
- 至少 10 块黑曜石；如果不用钻石镐挖黑曜石，可以用岩浆+水浇筑传送门。
- 防火药水、备用黑曜石和返回标记是强烈建议，不是硬性前置。

进入下界后的策略：

1. 到达后先停在传送门里观察区块加载，确认门外不是岩浆或悬崖。
2. 保护传送门，记住坐标，沿途用火把/方块做标记。
3. 找下界要塞，目标是烈焰人和下界疣；要塞通常需要走几百甚至上千格。
4. 打烈焰人优先用弓、方块遮挡和防火；不要在没有退路时贴脸。
5. 至少收集 6 根烈焰棒，做成 12 份烈焰粉；如果还要酿造，额外多收。

### 2.4 找要塞

末影之眼不是“用一次就找到要塞”：

- 抛出后看它飞行的方向，走一段再抛下一次。
- 眼睛会破碎，攻略建议准备 15 个以上；12 个只是激活传送门的最低数量。
- 眼睛向下落通常表示要塞在脚下，需要向下挖。
- 进入要塞后要标记入口、封死死路，沿石砖和门的方向寻找传送门房间。
- 传送门房间可能有蠹虫刷怪笼和岩浆，先清理威胁再填眼睛。

当前项目把“12 个末影之眼”直接当成“定位要塞”的前置，缺少“多准备几个、反复投掷、记录方向、向下挖掘、标记路径”的过程。

### 2.5 末地

末地战不是“站在岛上攻击末影龙”：

1. 进入末地先确认平台和地形，必要时用方块/末影珍珠回到主岛。
2. 先拆末影水晶，否则龙会持续回血。
3. 水晶有高塔、铁栏和不同高度；需要弓、方块、末影珍珠，必要时用床或水晶爆炸。
4. 龙停在传送门上方时再用剑近战；飞行阶段用弓。
5. 带水桶、缓降药水、末影珍珠或足够方块处理击退和坠落。
6. 只有龙死亡/退出传送门才是通关证据，不能靠“附近没有龙实体”推断。

### 3.2 为什么不是长攻略

长攻略适合人阅读，不适合每 8 秒一次的 Agent 决策：

- 会掩盖当前世界事实，模型容易复述攻略而不是观察现场。
- 版本差异和配方细节容易产生幻觉。
- 失败后没有明确的替代策略。
- 大量无关内容会稀释当前目标。

配方、掉落、工具等级继续使用项目本地的 `generated/*.json`；Wiki 只用来提取“什么时候做什么、为什么、失败怎么办”的策略。

## 4. 建议的知识分层

### 第 0 层：确定性数据

已有 `packages/agent/domain/knowledge`：

- 合成配方、熔炼配方、燃料。
- 方块掉落、实体掉落、工具等级。
- 所有查询都基于本地 1.20.1 数据，不让模型背配方。

这一层保持不变。

### 第 1 层：Playbook Cards

建议新增一个纯数据目录，例如：

```text
packages/agent/domain/playbook/
  types.ts
  cards/
    early.ts
    mining.ts
    nether.ts
    stronghold.ts
    end.ts
  selector.ts
  selector.test.ts
```

卡片只描述策略，不直接调用技能；卡片中的 `steps` 由现有任务生成器翻译成 `Task`。

### 第 2 层：卡片选择器

选择器输入：

- 当前维度、坐标、时间、生命、饥饿。
- 背包摘要、工具等级、装备、食物储备。
- 附近方块/实体、工作站、床、传送门。
- 当前阶段、最近失败类型和失败位置。
- 观众提议/目标约束。

输出：

- `activeCard`：当前最该做的一张卡。
- `alternatives`：最多两张备选卡。
- `reason`：为什么选它。
- `abortConditions`：什么时候该换卡。

模型不直接看全部卡片，只看当前卡和少量备选卡。

### 第 3 层：模型边界

模型仍然只做三件事：

1. 在已通过前置校验的候选任务中选择一个。
2. 用一句自然语言解释“为什么现在做这个”。
3. 在失败恢复时选择一张已经提供的恢复卡。

模型不能：

- 发明技能、方块 ID 或坐标。
- 直接修改阶段顺序。
- 绕过安全反射和前置条件。
- 把 Wiki 文本当成当前世界事实。

这样既保留人格表达，又不会把执行正确性交给语言模型。

### 第 4 层：失败诊断和情景记忆

建议把失败从“任意字符串”升级为稳定分类：

```text
NO_PATH
RESOURCE_NOT_FOUND
TOOL_TOO_LOW
STATION_UNREACHABLE
HAZARD_NEARBY
NIGHT_TOO_DANGEROUS
INVENTORY_FULL
TARGET_MOVED
NO_PROGRESS
TIMEOUT
```

每次失败记录：

- 失败任务、阶段、策略签名。
- 失败位置和附近地形。
- 失败时的生命/饥饿/时间/维度。
- 尝试次数和最后观察到的世界变化。

这些事实进入一个轻量 blackboard，例如：

```text
home: (38, 79, 191)
last_surface_exit: (39, 80, 191) — 两次 goto 都 stopped short
last_failed_route: mining-cave-east
known_fortress: null
portal: null
```

Agent 下次可以说“上次那条路走不通，我换一条”，而不是重复同一句“我再试一次”。

## 5. 与当前项目的差距

### 5.1 阶段顺序

实施前顺序：

```text
wood-and-table
-> stone-tools
-> food
-> iron
-> shelter
-> nether
-> eyes
-> stronghold
-> dragon
```

问题：

- 新手攻略把庇护所/床放在第一天，通常早于铁器。
- 当前把铁器放在庇护所前，导致 Agent 夜里没有床，只能靠“保持移动”保命。
- 食物和庇护所更适合作为“跨阶段安全需求”，而不是完全串行的阶段。

已落地方向：

```text
wood-and-table
-> stone-tools
-> food（当前饥饿）
-> shelter（床、照明、安全屋）
-> iron（铁器、铁甲、盾牌/弓的准备）
-> nether
-> eyes
-> stronghold
-> dragon
```

`shelter` 现在排在 `iron` 前，夜间回家/留守也已经是跨阶段检查。食物储备不是硬
里程碑：进入铁器及之后阶段时，只要白天、当前不饿且眼前已有动物/掉落食物/小麦，
规划器会先补到 3 份；看不见目标时不会为了凑数无限探索。

### 5.2 缺失的前置条件

当前阶段没有明确建模：

- 铁甲、盾牌、弓和箭。
- 水桶、打火石、备用方块。
- 食物储备（不只是“当前不饿”）。
- 下界传送门的点燃工具。
- 末地战斗的弓、方块、水桶、缓降/末影珍珠。
- 要塞探索的火把、封路材料和 15+ 末影之眼。

### 5.3 终局里程碑已可确认（已修）

原来的 `dragon-dead` 判定是：

```text
附近实体里没有 dragon -> unverified
附近实体里有 dragon -> incomplete
```

这永远不会变成 `complete`。现在身体通过服务端 `AFTER_DEATH` 事件记录末影龙死亡，
快照上报 `dragonDefeated=true`，规划器据此完成 `dragon-dead`。附近没有龙仍然只是
`unverified`，不会被误当成“已击杀”。

### 5.4 失败恢复已分类（已修）

现在主要做的是“同一策略失败两次后换候选”。但真实玩家会先判断：

- 是没找到目标，还是目标不可达？
- 是路线失败，还是工作台不可达？
- 是工具不对，还是夜间/危险？
- 是物品满了，还是目标移动了？

现在失败会先归类为 `NO_PATH` / `RESOURCE_NOT_FOUND` / `TOOL_TOO_LOW` /
`STATION_UNREACHABLE` / `NIGHT_TOO_DANGEROUS` / `INVENTORY_FULL` /
`NO_PROGRESS` / `TIMEOUT`。背包满、工具损坏和夜间危险不会原样重试；连续失败后的
换区域逻辑也复用同一分类。

### 5.5 模型候选和文案错位（已修）

实机 `decision_log` 中出现过：

- 理由写“合成木板”，实际技能是 `descend`。
- 理由写“返回地表”，实际技能仍然是 `descend`。

这不是知识问题，而是 `AutonomousGoalPlanner` 复用了缓存 `reason`，但候选技能已经变化。现在文案只在候选 `strategyKey` 一致时复用，否则回退到当前候选文案并清空缓存。

### 5.6 从矿洞回地表不能只靠长距离 `goto`（已改）

实机中多次出现：

```text
safe route stopped short of the requested target
```

目标在地表，但身体在矿洞，普通 A* 没有可站立路径。现在：

- 返地表目标按 12 格一段生成，下一轮快照再继续上升。
- 露天坑底不再被误判成深层矿洞，避免“要求返地表但返地表任务拒绝生成”的死锁。
- 后续仍建议把“沿已挖阶梯上升”做成身体侧专用宏，减少对 `goto` 逃生的依赖。

## 6. 建议的第一阶段改动

### P0：先让早期体验像会玩

1. ✅ 调整阶段顺序：石具后优先安全屋/床，再进入铁器。
2. ✅ 增加夜间策略：有床优先睡觉；没床继续挖矿、制作或整理物资，不挖临时避难洞；
   近身空手威胁也只逃跑/求援，不再用竖井拖时间。
3. ✅ 增加食物储备候选，而不是只看当前饥饿值，也不把它写成硬里程碑。
4. ✅ 修复 `reason`/`speech` 缓存与候选技能错位。
5. ✅ 增加失败分类，并禁止背包满/工具损坏/夜间危险的原地重试。
6. ✅ 把返回地表改成 12 格一段的阶梯上升流程，并修复露天坑底误判。
7. ⏳ 用 10 次新世界跑测验证：第一夜存活率、床完成率、石具完成时间。

### P1：让中局能持续发育

1. 铁甲、盾牌、弓/箭、水桶、打火石、备用方块。
2. 下矿前检查：食物、火把、工具耐久、返回路线、背包空间。
3. 下界准备卡：黑曜石、点燃工具、防火、标记传送门。
4. 要塞卡：15+ 末影之眼、反复投掷、记录方向、向下挖、标记路径。

### P2：让终局闭环

1. 末影水晶目标、龙停靠时的近战窗口、飞行阶段弓箭。
2. 坠落/击退/虚空防护。
3. 末影龙死亡事件作为唯一通关证据。
4. 将传送门、要塞、下界要塞、失败地点写入长期记忆。

## 7. 验收指标

不要只用“看起来在动”验收，建议记录：

- 从新世界到石镐的中位时间。
- 第一夜存活率。
- 天黑前有床/封闭安全屋的比例。
- 同一失败策略连续重试次数。
- 每次决策的理由与技能是否一致。
- 从石具到铁镐、从铁镐到下界、从下界到末影之眼的中位时间。
- 每个阶段的人工接管次数。

建议每次决策额外记录：

```text
playbook_id
playbook_reason
failure_code
recovery_id
memory_version
```

这样后续才能回答“Agent 是知识不够、执行失败，还是恢复策略错误”。
