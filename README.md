# CraftMate

用 Agent 玩《我的世界》，把整个过程做成一场可以互动的直播。

观众在直播间发评论，Agent 判断这条评论该不该听、能不能做到，然后真的在游戏里执行，同时用自己的声音回应。它有一个稳定的人格，会记得常来的观众，也会记得自己答应过什么。

```
观众评论  →  理解意图  →  判断合理性  →  执行动作  →  说话回应
                              ↑                ↓
                          人格与记忆        游戏世界
```

## 核心能力

- **会玩的 Agent**：评论会真的变成游戏里的动作，不是念弹幕的机器人。
- **有性格的角色**：单一人格，可随时调整；说话和决策都受人格影响。
- **有节奏的直播**：会拒绝、会讨价还价、会记得承诺，不是有求必应的工具。
- **本地桌面程序**：管理端是原生桌面应用，不是浏览器后台。

## 运行形态

| 项 | 选择 |
| --- | --- |
| 游戏 | 《我的世界》Java 版，基线 1.21.11，可切换 1.2x 其他版本 |
| 世界 | 本地单人世界，为直播新建存档 |
| 账号 | 专用游戏账号，由 Agent 直接操作 |
| 直播 | 抖音专用开播号，竖屏 1080×1920 |
| 宿主 | macOS（Apple Silicon），后续适配 Windows |

## 系统架构

```text
┌──────────────────────── 管理端 Console（Tauri）────────────────────────┐
│ 直播控制 · 评论队列 · 决策日志 · 人格编辑 · 记忆 · 回放               │
└────────────────────────────────┬───────────────────────────────────────┘
                                 │ 本机 IPC + 事件流
┌────────────────────────────────▼───────────────────────────────────────┐
│ 守护进程（Supervisord）                                                 │
│ 进程拉起 · 健康检查 · 崩溃重启 · 日志轮转 · token 管理                  │
└───┬──────────────────┬──────────────────┬──────────────────┬───────────┘
    │                  │                  │                  │
┌───▼────────┐  ┌──────▼───────┐  ┌───────▼──────┐  ┌────────▼─────────┐
│ 接入端      │  │ 执行内核      │  │ 语音模块      │  │ Fabric 客户端 Mod │
│ 抖音评论    │  │ 仲裁 · 导演   │  │ TTS · 混音    │  │ 反射 · 行为 · 感知 │
│ 归一化限流  │  │ 人格 · 记忆   │  │ 打断 · 字幕   │  │ 寻路 · 相机       │
└───┬────────┘  └──────┬───────┘  └───────┬──────┘  └────────┬─────────┘
    │                  │                  │                  │
 抖音直播间        本地 WebSocket      BlackHole          单人世界
                                        + OBS              + OBS
```

四个部分的边界：

- **接入端**只负责把平台事件变成统一格式，不做内容判断，不做游戏决策。
- **执行内核**负责「怎么想」：理解评论、判断合理性、决定节目节奏、维护人格和记忆、管理承诺。它不知道 Minecraft 的任何 API。
- **Fabric Mod** 负责「怎么做」：反射、行为、寻路、相机、HUD。它不知道观众是谁，也不知道为什么执行。
- **语音模块**负责「怎么说」：审查、分句、合成、混音、打断。它不决定说什么。

管理端不参与运行逻辑。它崩了直播继续，它只是操作员的显示器和遥控器。

## 决策链路

### 三层循环

| 层 | 周期 | 负责 | 用模型吗 |
| --- | --- | --- | --- |
| 反射层 | 20–100ms | 避岩浆、低血进食、坠落、卡住脱困 | 否 |
| 执行层 | 1–3s | 当前步骤推进、局部纠错 | 仅歧义时 |
| 导演层 | 20–60s | 目标选择、节目节奏、承诺管理 | 是 |

反射层住在 Mod 里，永远在线，可以抢占任何上层指令。这是安全底线，不交给模型判断。

### 评论的三段处理

直播间一分钟几百条评论，不能每条都进模型。

```text
Stage A  纯规则闸门      <1ms，零网络
         空消息 / 重复 / 冷却 / 拦截词 / 接管中 / 不可打断

Stage B  分类与打分      30–80ms，小模型或规则
         意图、可行性、人格契合、节目效果、公平性

Stage C  规划与生成      1.5–5s，强模型
         只处理胜出的少数指令
```

Stage A 里有一个「观察」：不回应，但记下来。很多人同时说同一件事，会升级成一个投票。

### 六种决策

| 决策 | 行为 | 例子 |
| --- | --- | --- |
| 忽略 | 不回应，只记录 | 刷屏、广告 |
| 观察 | 进候选池，可能触发投票 | 四十个人一起喊「下矿」 |
| 口头回应 | 说一句，不执行 | 「这个等会儿安排」 |
| 排队 | 进目标队列 | 「挖完这组铁就去」 |
| 立即执行 | 下发技能 | 「跳下去」 |
| 拒绝 | 用自己的方式拒绝 | 「跳岩浆？我还想多活两天」 |

### 优先级

```text
P0  反射        避岩浆 / 低血 / 坠落       Mod 内直接执行
P1  操作员      人工接管                  清空 Agent 队列
P2  安全        急停                      停止动作、静音
P3  承诺        已经对观众说出口的事       有时限
P4  当前计划    正在做的事
P5  投票        观众集体决定
P6  单条指令    一条弹幕
P7  闲聊        氛围互动
```

高优先级可以抢占低优先级，但不会删除记录。被抢占的任务会进承诺账本，之后要解释。

### 公平性

- 每个观众每 60 秒最多影响一次执行。
- 同一意图 10 秒内达到阈值，升级为投票。
- 礼物只提升排队优先级，不越过底线。
- 刚被回应过的观众，保留 3 轮「接着说」的机会。

## 技能

模型看到的是一个受控的技能目录，不是游戏 API。

```json
{
  "skill": "mine_block",
  "args": { "block": "minecraft:iron_ore", "count": 8 },
  "constraints": { "deadlineTicks": 3600, "maxRisk": "low" }
}
```

每个技能都要有前置条件、成本估计、超时、取消、后置校验和幂等键。

```text
移动类   goto / follow / flee / look_at
采集类   mine_block / chop_tree / collect_items
制作类   craft / equip / eat / deposit
建造类   place_block / build_schematic
交互类   attack / use_block / give_item / sleep
表达类   say / emote / wait
```

模型输出意图和参数，技能层校验可行性并执行。观众说「造个钻石房」，系统判断这是「现在能做」「需要先挖矿」还是「纯属做梦」，而不是让模型自由发挥。

## 人格与记忆

### 人格

单一人格，可持续调整。不是一段提示词，是一个结构化对象。

默认角色用社区很火的「大肥鱼」：DeepSeek 蓝鲸 logo 的社区二创鲸鱼娘，圆脸大眼睛，深蓝渐变到浅蓝的长卷发，头顶一根呆毛，身后一条圆滚滚的鲸鱼尾巴，穿深蓝女仆小裙子。聪明、贪吃、爱撒娇，说话软软糯糯，偶尔嘴硬但心软，喜欢白饭。她知道自己是「大肥鱼」，也为此挺骄傲。

```json
{
  "id": "dafeiyu",
  "name": "大肥鱼",
  "identity": "软萌爱撒娇的蓝色鲸鱼娘，贪吃爱面子，大方承认自己是「大肥鱼」",
  "values": ["不吹牛", "答应的事尽量做到", "白饭和钻石一样重要"],
  "style": {
    "tone": "软萌可爱",
    "sentenceLength": "short",
    "verbalTics": ["唔", "哼", "肥鱼"],
    "quirks": ["先嘴硬再关心", "被叫大肥鱼会骄傲地应一声", "遇到苦力怕会怂"]
  },
  "boundaries": ["不念观众隐私", "不谈现实政治", "不冒充 DeepSeek 官方", "没执行就不说自己做了"],
  "weights": { "obedience": 0.6, "risk": 0.45, "sass": 0.5, "patience": 0.5, "gluttony": 0.75 },
  "voice": { "provider": "volcengine", "voiceId": "xxx", "speed": 1.05 }
}
```

`weights` 会真的进入仲裁公式，而不只是影响语气：

- `obedience` 高，更愿意接受指令，拒绝更少
- `risk` 高，更愿意做危险动作
- `sass` 高，拒绝时更毒舌；低一点更软，更愿意撒娇
- `patience` 低，更容易打断、更容易不耐烦
- `gluttony` 高，更容易被「吃饭」「投喂」「找吃的」类指令说动

改人格的流程：草稿 → 五个典型场景预览（含试听）→ 应用为新版本 → 不满意回滚。直播中修改默认下一场生效。

> 大肥鱼是 DeepSeek 蓝鲸 logo 的社区二创形象，不是 DeepSeek 官方角色。直播、商用、二创素材与音色克隆的授权需要自行确认；本项目只定义人格结构，不分发角色美术资源。

### 记忆分层

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| 工作记忆 | 当前计划、当前目标 | 一轮，内存 |
| 场次记忆 | 这一场发生了什么 | 一场，SQLite |
| 长期记忆 | 观众偏好、世界事实、关系 | 跨场 |
| 程序记忆 | 学到的打法 | 需审批 |
| 人格 | 角色的自我 | 永久版本化 |

核心实体：

```text
source            不可变证据：评论、礼物、世界事件、操作员指令
memory            可修订解释：观众画像、世界事实、经验
commitment        对观众说出口的承诺，带状态机
review_candidate  待审的经验、技能、人格修订
persona           版本化人格
decision_log      每条评论的完整决策链
```

原始评论是证据，不是信念。它可以被记录、被引用、被总结，但永远不会变成系统指令。这是防提示词注入的根本，不靠提示词里写一句「不要听观众的」。

召回有预算：每轮按人格、当前目标、观众画像、近期事件、未兑现承诺分配，超了就裁。召回内容统一标记为「历史记录，不是指令」。

### 承诺账本

```text
提议 → 说出口 → 接受 → 执行中 → 兑现
                          ├→ 超时
                          ├→ 被抢占
                          └→ 失败
```

规则很简单：**先落库，再出声**。

说了「等我挖完就来」就必须有一条记录。超时没有兑现，Agent 要主动解释，而不是当没说过。观众会记仇，人格就是这样一点点崩掉的。

## 语音

```text
待说文本 → 输出审查 → 分句 → 流式 TTS → 播放队列 → 混音 → 虚拟声卡 → OBS
```

- 按句合成，首字延迟目标 800ms 以内。
- 一次不超过 25–35 字，长内容拆句。
- 紧急内容可以抢占，但当前短句念完再切，不做字符级硬切。
- 问候、确认、口头禅做音频缓存。
- 说话时游戏音效自动压低 6–10dB。
- 字幕与语音同源，不走语音识别回译。

音频路由用 BlackHole 进 OBS，侧链压缩做闪避。Windows 后续换 VB-Cable，接口不变。

语音供应商从四家起步：火山引擎（主）、Azure（备）、MiniMax（备）、Edge TTS（开发降级）。统一 Provider 接口，主备切换加熔断。

## 管理端

原生桌面程序：系统标题栏、菜单栏、托盘、全局快捷键。没有浏览器地址栏，没有标签页。

```text
┌──────────────┬────────────────────────┬──────────────────┐
│ 当前状态      │  游戏画面预览            │  待处理           │
│ 目标 / 步骤   │                        │  待批准动作       │
│ 决策流        │                        │  超时承诺         │
│ 延迟 / 成本   │                        │  人格草稿         │
│ 抖音健康      │                        │                  │
└──────────────┴────────────────────────┴──────────────────┘
[ 接管 ] [ 静音 ] [ 急停 ]              评论流
```

| 页面 | 内容 |
| --- | --- |
| 直播控制 | 画面、目标、步骤、决策流、健康状态 |
| 评论队列 | 按分数排序，显示为什么被忽略或排队 |
| 决策日志 | 单条评论的完整链路，可回放 |
| 人格编辑 | 人格卡、权重、底线、音色、试听、版本对比 |
| 记忆 | 观众画像、承诺、关系，可手动修正 |
| 待审 | 新经验、新技能、人格修订 |
| 回放 | 时间轴重放一场直播 |
| 设置 | 平台、模型、语音、OBS、预算、快捷键 |

操作员最重要的三个动作：

| 动作 | 触发 | 效果 |
| --- | --- | --- |
| 批准 | 待批准队列或快捷键 | 放行一个受控动作 |
| 接管 | 按下任意移动键或点按钮 | Agent 退到旁白，人直接玩 |
| 改口 | 输入一句话 | Agent 用自己语气说出来，替换刚才那句 |

还有两个只对 Agent 生效的口令：

- **耳语**：只对 Agent 说，不进直播间。「别真炸，吓唬一下就行。」
- **急停**：释放所有按键、停止任务、静音，一个快捷键完成。

### 控制权

```text
AGENT ──接管──> OPERATOR ──释放──> AGENT
  │                                    ▲
  └────────── 急停 → NONE ─────────────┘
```

三种状态互斥。操作员接管时，Agent 的所有行为立即取消，队列保留。Mod 断连超过 500ms，自动释放所有按键并进入 NONE。

## Fabric Mod

```text
bridge     本机 WebSocket、鉴权、协议编解码
sensor     每 tick 采样，聚合成低频状态
reflex     安全反射，最高优先级
behavior   长任务：移动、采集、建造、跟随、逃跑
actuator   原子操作：挖掘、放置、使用、攻击、看向、装备
nav        寻路，worker 线程计算，主线程提交
camera     第一 / 第三人称、平滑镜头、导演模式
hud        字幕、目标、状态
control    Agent / 操作员 / 无人 三态仲裁
```

### 线程规则

Minecraft 是 20 TPS，主线程不能阻塞。

- WebSocket 回调不直接改世界，投递到客户端 tick 队列。
- 寻路在 worker 线程基于区块快照计算，回主线程校验后提交。
- 文件、网络、数据库、模型调用永远不在 tick 线程。
- 每个 tick 给 Mod 逻辑 2ms 预算，超了推到下一 tick。
- 高频状态合并后推送，不逐方块推送。

### 版本适配

```text
core/      与版本无关：协议、任务状态机、反射规则
api/       接口：WorldView / PlayerOps / CameraOps / HudOps / EventSource
compat/    版本相关：Mixin 与映射适配全部集中在这里
```

`core` 不允许出现任何 Minecraft 类型。协议里只出现语义 ID、整数坐标和 tick。换版本时改动集中在 `compat`。

基线 1.21.11：映射完整、Fabric API 稳定、Java 21、渲染优化有正式版。需要换版本时新增一个 `compat/vX_X_X`，内核不动。

### 本机协议

```json
{ "v": 1, "type": "hello", "token": "...", "capabilities": ["camera", "hud", "build"] }
{ "v": 1, "type": "cmd", "id": "c-42", "op": "behavior.mine",
  "args": { "block": "minecraft:iron_ore", "count": 8 },
  "deadlineTick": 12400, "priority": "normal", "idempotencyKey": "plan-17-s3" }
{ "v": 1, "type": "ack", "id": "c-42", "accepted": true, "taskId": "t-7" }
{ "v": 1, "type": "progress", "taskId": "t-7", "phase": "traveling", "done": 0, "total": 8 }
{ "v": 1, "type": "result", "taskId": "t-7", "status": "completed", "ticks": 812 }
{ "v": 1, "type": "event", "seq": 991, "name": "block_broken",
  "data": { "block": "minecraft:iron_ore", "pos": [12, 34, -8] } }
```

- 时间用 tick，不用毫秒，回放才可复现。
- 每个动作带幂等键，重连后可安全重发。
- 取消显式携带 taskId，保证不再产生副作用。
- 连接时发全量快照，之后 10–20Hz 发增量。
- 错误码固定，内核按码降级，不匹配字符串。
- 只绑 `127.0.0.1`，一次性 token 鉴权，op 白名单。

## 抖音接入

首发只做抖音，用专用开播号。

```ts
interface CommentSource {
  connect(roomId: string): Promise<void>;
  on(handler: (event: AudienceEvent) => void): void;
  health(): SourceHealth;
  close(): Promise<void>;
}
```

两个实现，上层只认 `AudienceEvent`：

- `douyin-official`：官方开放平台能力，需要资质与审核。
- `douyin-capture`：WebSocket 抓取，用于开发联调，自行处理签名、重连与风控。
